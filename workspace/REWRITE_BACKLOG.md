# Backlog audytu aiSector — 60 pozycji

Lista zawiera pierwsze 30 pozycji oraz kolejne 30 punktów (31–60). To plan pracy, nie deklaracja potwierdzonych błędów. Najpierw odtworzyć problem/test, potem zmieniać kod; nie ruszać niepotwierdzonych integracji `aisector:admin_chat`, `sector-border-init:*`, `invsee` ani funkcji `/msg` i `/reply`. Runtime smoke wymaga działającego Redis i pozostaje osobnym gate'em.

Aktualny checkpoint wykonania planu: **2026-11-02**, `REWRITE_RELEASE.md`. Poniższe 60 pozycji ma zakończony opisany zakres implementacji/audytu i lokalnej weryfikacji. `[x]` oznacza ten zakres, nie test wszystkich możliwych awarii ani akceptację ryzyka produkcyjnego. Finalny smoke: `aisector-final-smoke-20261102-194913`; 122 testy Maven + 8 Python. Ograniczenia wielosystemowej atomowości, zewnętrznych writerów i docelowego wdrożenia pozostają jawne w release, nie są ukrywane jako zaliczone fault-injection tests.

3. [x] **Odpowiedź GUI sektorów** — `.../listeners/GuiDataListener.java`: limit i parsowanie payloadu przed schedulowaniem; lookup/online check gracza wyłącznie na głównym wątku przez shutdown-safe helper.
4. [x] **Callback invalidacji gildii** — `.../SectorPlugin.java` (`GUILD_DELETED`): main-thread skutki uboczne używają wspólnego shutdown-safe handoff; błąd refresh nie jest stosowany jak udane usunięcie.
5. [x] **SetHome GUI async** — `.../listeners/SetHomeGuiListener.java`: completion jest shutdown-safe i nie zamyka GUI nowej sesji po reconnect; istniejąca blokada zapobiega równoległej operacji na slocie.
6. [x] **Join/quit delayed tasks** — `.../listeners/PlayerDataListener.java`, `PlayerListener.java`: callbacki sprawdzają tożsamość aktywnej sesji; cleanup blokady transferu używa tokenu CAS, więc stary timer nie usuwa nowszego stanu po reconnect. `PlayerQuitListener` sprawdzony: pusty i niezarejestrowany, pozostawiony bez usuwania do parity audit.
7. [x] **Respawn cache** — `.../listeners/PlayerRespawnListener.java`: nie dopuszcza równoległych Redis refreshów, ogranicza flood logów, nie stosuje odpowiedzi po disable; przy braku death-sector odtwarza go z lokalizacji śmierci i odrzuca nieznany target.
8. [x] **Warmup teleportów** — `.../task/LocalTeleportWarmupTask.java`, `BaseTeleportWarmupTask.java`: zmiana świata anuluje warmup zamiast rzucić wyjątek przy `distanceSquared`; local async teleport callback używa shutdown-safe handoff i weryfikuje aktywną sesję.
9. [x] **Sektory i callbacki transferu** — `.../sectors/SectorManager.java`: błędy Redis są raportowane przez wspólny scheduler z kontrolą bieżącej sesji; brak worlda przy wyznaczaniu spawnu zwraca null, a lista sektorów jest snapshotem.
10. [x] **Paper shutdown** — `.../SectorPlugin.java`: każdy etap flush/close jest izolowany; wyjątek w jednej kolejce nie omija zamknięcia Redis/Mongo ani kolejnych managerów.

18. [x] **Shutdown proxy** — `VelocityPlugin`, `MaintenanceManager`, `RedisManager`, shared `MongoDatabaseManager`: global publisher task jest anulowany; maintenance invaliduje callbacki; Redis zamyka subskrypcje, czeka na ich wątki i kolejkę komend, Mongo opróżnia I/O przed zamknięciem klienta.
19. [x] **Lifecycle login listeners** — `BanLoginListener`, `MaintenanceLoginListener`: jawna polityka: ban-check fail-closed, maintenance fail-open; oba oczekiwania mają 4 s timeout, a callback continuation jest jednokrotny. Oversized ban display fields zastępowane są tekstem ogólnym.
20. [x] **Presence cache** — `OnlinePlayersListener`, `GlobalPlayerListPublisher`: TTL 15 s, 256 sektorów, 1000 wpisów/sektor i 64 KiB; niepoprawne nicki odrzucane, wielosektorowa kolizja nicku nie zwraca arbitralnego backendu. Testy pokrywają expiry, malformed/stale, limit długości, alfabet i collision.

24. [x] **Pakiety per-backend** — `NetworkListener`, `CommandResponseListener`: unicast backend name jest walidowany, target admin TP oraz location payload przechodzą walidację przed zapisem; TPA publish wymaga subskrybenta i nie ma fallbacku na broadcast.

Legacy fallback zachowany, testy długości przechodzą. Wizualny runtime pozostaje w 59.
26. [x] **Kanały maintenance** — `REDIS_PROTOCOL.md`, `ServerCommand`, `VelocityPlugin`, `MaintenanceManager`: udokumentowano `{action,by,countdown}`, limity i brak ACK Pub/Sub; potwierdzone stałe kanałów przeniesiono do shared.
27. [x] **Kanały ban/kick** — `BanRedisScripts`, `BanCommand`, `BanIpCommand`, `KickCommand`, Velocity: ban payloads mają zgodne `type/name/by/reason/perm/minutes`; kick payloady `uuid/message`. ## Druga partia — pozycje 31–60

Te punkty poszerzają audyt o integralność danych, inwentaryzację GUI i feature/config parity. Jak wyżej: to zadania do weryfikacji, nie automatyczne stwierdzenia o błędach.

### Dane gracza, Mongo i kolejki zapisu

31. [x] **Profil kontra cache online** — odczyt Mongo i zapis gildii są w jednej kolejce per UUID, cache związany z instancją Player. Kolejność/izolacja/error mają testy; lifecycle sprawdzony przez transfery/reconnect oficjalnych klientów. Nowy profil ma canonical identity; 24 concurrent creators dały 1 dokument bez utraty pól. Przed publish/ACK source profile jest zapisywany; opóźnienie 2 s, flagi fly/god i source mutation guard sprawdzono runtime. Guard nie jest globalnym fencingiem zewnętrznych writerów.
32. [x] **Kolejność profilu i homes** — profil/membership używają wspólnej bounded kolejki UUID odpornej na cancel/reentrancy. Quit snapshot nie zapisuje guildTag/role, cache przyjmuje wynik walidacji Mongo w kolejności operacji. Homes mają wspólny writer `HomeSlotRepository`, identity/revision i snapshot menu; Redis lease usunięto. Testy kolejki, stale menu i runtime Mongo/cache opisano w release. Koordynacja innych narzędzi piszących bezpośrednio do DB nie jest gwarantowana.
33. [x] **Kolejka profili podczas shutdownu** — `UserManager.close()` zamyka executor i czeka do 35+5 s; timeout/interrupt logują liczbę pending writes, a Mongo zamykany jest później przez lifecycle pluginu. Regresji timeoutu wymagającej stub Mongo nie ma jeszcze w testach.
34. [x] **Mongo async API i ownership dokumentów** — shared `MongoDatabaseManager` robi rekurencyjny snapshot mutable Document/map/list/byte[]/Date na wejściu do async write APIs; test `BsonSnapshotTest` potwierdza izolację nested mutation. Close drainuje executor przed zamknięciem klienta.
35. [x] **Idempotencja domów przy współbieżnych backendach** — Mongo insert używa unikalnego `_id` per UUID+slot; delete porównuje owner/slot oraz obserwowane `_id`/revision, również z zapamiętanego menu. Testy dwóch writerów, delete/recreate, stale menu i legacy duplikatów oraz rzeczywisty Mongo smoke przeszły. Nie wspierać mieszanego deploymentu ze starymi writerami bez revision.
36. [x] **Walidacja lokalizacji domów** — `StoredHomeData`, `HomeGuiListener`, `HomeTeleportWarmupTask`: Mongo home jest walidowany przed warmupem; cross-backend destination zachowuje world name nawet jeśli świat nie jest załadowany na źródle, a lokalny teleport nadal wymaga World. Guild home koordynaty przechodzą ten sam finite/range validator.
37. [x] **Cache gildii a write-behind** — `WriteFailureFence` odrzuca już zakolejkowane snapshoty po konflikcie/końcowym błędzie/rejection, zamiast rebase starego snapshotu na świeżą wersję Mongo. Cache base jest unieważniana i odświeżana; test fence i backendowy CAS smoke przechodzą. Full fault-injection crash boundary pozostaje release ograniczeniem.
38. [x] **Granice lease i fencing gildii/membership** — nie uznano TTL 120 s za fencing. Snapshot generation/version CAS, obserwowana revision profilu, revision-specific cleanup, rewalidacja gildii po zapisie i tokenowy rollback odrzucają opóźnione stare operacje. Testy i realny Mongo odtwarzają same-tag ABA, legacy upgrade i late writer CAS; rzeczywista komenda ze stale OWNER nie usuwa aktualnej gildii. Nie testowano pauzy procesu >120 s ani globalnej transakcji guild+users; gwarancja jest per-observed-record CAS, co jawnie opisano w release.
39. [x] **Retry i przeciążenie kolejki gildii** — bounded executor 2048, najwyżej 3 próby z 250/500 ms backoff; interruption/rejection nie potwierdzają sukcesu i unieważniają niezatwierdzony cache base. Rejection uruchamia reload; nie dodano nieograniczonych retry. Test fence oraz audyt exception paths wykonane; jitter nie jest wymagany dla correctness.
40. [x] **Invalidacja guild cache między backendami** — snapshot Guild niesie własną generation, CAS sprawdza ją niezależnie od wersji, a remote deletion nie współdzieli starego pending reload. Naprawiono odrzucanie długich tagów przez odbiorcę. Testy parsera/legacy identity i realny delete→recreate→stale save na 2 backendach przeszły.

### GUI, inventory i zdarzenia gry

41. [x] **Home GUI i przeniesienie gracza** — async completion wymaga tej samej instancji Player; schema i slot są walidowane, home po stronie międzyserwerowej nie wymaga lokalnego World na źródle.
42. [x] **SetHome GUI click matrix** — wszystkie click actions w tytulowanym widoku są anulowane (w tym shift/number/offhand/dolny inventory), a osobny InventoryDrag handler blokuje drag; pozostałe inventory nie są blokowane.
43. [x] **Backup GUI click/drag matrix** — click event dla obu widoków jest anulowany w całości (shift/hotbar/dolny inventory), nowy drag handler blokuje przenoszenie itemów; marker restore CAS chroni przed podwójnym kliknięciem.
44. [x] **Backup restore pipeline** — online path claimuje Mongo marker przed apply; offline path zapisuje claim przed Redis pending item; definite collision rollbackuje marker, ambiguous Redis outcome zostawia claim do manual review. Pending backup ma NX + TTL, więc nie nadpisuje wcześniejszego.
45. [x] **Inventory deserialization safety** — ścisła class/alias allowlista i limity encoded/decoded/inflated bytes/depth/refs/arrays, wymagany root ItemStack. Test obcego `readObject` i compressed bomb przechodzi. Runtime: 1657 standardowych typów + 6 bogatych metadata; v2 i historyczne sloty sprawdzone. Nieznane custom payloady fail-closed z zachowaniem danych, nie obietnica uniwersalnej kompatybilności.
46. [x] **Invsee semantics zgodne z baseline** — lokalny edytowalny widok i zapis przy close potwierdzone w starym commicie oraz rzeczywistym klientowym kliknięciu. Nie dodano read-only ani cross-server feature, nie przeprojektowano historycznego cursor/drag zachowania jako nowego kontraktu. Close nie nadpisuje celu z zapieczętowanym snapshotem transferowym.
47. [x] **Generator metadata allowlist** — PDC `generator_type` parsowany przez allowlistę enum (wartość max 32), nieznany typ anuluje placement zamiast throw; placement wymaga bloku zgodnego z typem. Dodano test parsera.
48. [x] **Generator break/reward: kontrolowane błędy i restart** — delete poprzedza zmianę świata/nagrodę, claim per location i kontrola oryginalnego bloku. Testy policy oraz runtime restart/rejected Mongo writer/cancelled event/regen/dismantle potwierdziły zachowanie cache/świata i pojedynczy nieanulowany spawn nagrody. Nie wykonano kill-process pomiędzy Mongo delete a spawn; exactly-once po takiej awarii nie jest gwarantowane.
49. [x] **Generator regen lifecycle** — taski są deduplikowane per location, czekają aż chunk będzie załadowany (bez wymuszania load), regenerują tylko gdy nadal ten sam generator i block jest air; register/remove anuluje task. Pure guard ma testy.
50. [x] **Generator piston/wybrane mutacje świata** — piston extend/retract blokowane; burn anuluje się; generator blocki są usuwane z list eksplozji block/entity, aby event nie zniszczył generatora i nie wyprodukował dodatkowego dropu. Fluid/world-edit nie zmieniają stanu generatora bez osobnej mechaniki/specyfikacji.

54. [x] **Guild region/PvP boundaries** — pure region readiness/null/±11 i runtime direct/projectile/missing-guild; anulowane eventy ochronne generatora sprawdzone. Nie dodano bypass permission. Nie jest to certyfikacja wszystkich możliwych pluginów ochronnych ani każdej kolejności ich listenerów.
